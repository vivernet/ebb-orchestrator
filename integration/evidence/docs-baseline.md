# Baseline: README и .env.example

Дата: 2026-10-02. Метод: проверка доступного canonical набора `source/skills` и применение его опубликованных правил к трём фиксированным сценариям **до** создания нового skill. Это static gap/application assessment, не запись поведения независимого агента. Настоящие project README, config loaders и `.env.example` в предоставленном source snapshot отсутствуют; аудит их содержания не выполнялся.

Проверены `ebb-repository-maintenance`, его documentation checklist, `ebb-repository-context`, `ebb-quality-gates`, `ebb-curate-skills`; поиск `README|env.example|docs:*` по canonical skills. В maintenance уже есть command-source verification и аккуратное сохранение identifiers; context ограничивает чтение текущим scope, quality-gates требует свежего evidence. Но отдельного owner/trigger для README-content и environment examples нет. `source/package.json` объявляет docs governance scripts; их implementation в snapshot отсутствует, поэтому фактическая доступность/поведение не доказаны.

Вывод: `NEW_EBB` для owner содержания README и `.env.example`. File rename/move/delete/cleanup и restructuring остаются у `ebb-repository-maintenance`; общая completion policy — у `ebb-quality-gates`. Caller routing будет проверять controller; workflow не должен дублироваться в callers. Baseline показывает отсутствие capability contract в доступных инструкциях, а не эмпирически доказанную частоту ошибок агентов.
