# Proposal 13 — Совместимость Local Mode с разрешениями хоста

**Статус технического контракта:** Accepted для ограниченного Task5B-H Windows/Linux после независимого Plan20/security re-review от 2026-10-09 без blocking findings. Пользователь 2026-10-09 явно утвердил направление: убрать проверку и отклонение существующих host ACL ради запуска продукта, сохранить установленные пользователем разрешения и поддержать Windows, Linux и macOS. Host ACL inventory, remediation и повторное согласование сохранения этих разрешений не являются prerequisite. Acceptance этого контракта разрешает реализацию Task5B-H, но не подтверждает её выполнение, native acceptance или готовность платформ. Обязательный macOS port Task5A-M требует собственного design/review до реализации.

## Решение и границы

Local Mode доверяет конфигурации хоста и доступу, предоставленному ОС. Существующие volume roots, user-profile ancestors, Hermes install/source/runtime/auth root и общий `profiles` не являются приватными объектами Ebb. Их owner, ACL/mode, foreign grants, inherited FullControl, generic rights или особенности ACE не проверяются как admission predicate. Product и acceptance helpers не выполняют host permission inventory, не требуют его от оператора и не изменяют ACL, owner или mode существующих объектов ради запуска. Proposal12 superseded; ACL allowlist и root-only rights exception Proposal11 больше не задают admission policy.

Репозиторий, модель, prompts, runtime output и управляемый агент остаются недоверенными. Host trust не предоставляет им новых Action Gateway capabilities и не меняет approval, permission, scheduling или integration policy. Существующие OS-authorized principals входят в доверенную среду Local Mode; это не обещание OS sandbox против hostile same-user, administrator или другого пользователя с предоставленными host правами.

Приватная граница начинается на exact новом `profiles/ebb-orchestrator-run-<runId>`, включая его `home`, `config.yaml` и descendants. Ebb-owned source cache, staging, snapshot, sidecars и lock files также остаются приватными. Новые объекты получают private DACL/mode атомарно при создании; private owner/permission, nofollow, type, single-link и inventory checks сохраняются при повторном использовании и cleanup. Существующий общий `profiles` не переприватизируется; если он отсутствует, создаётся только нужный directory, без изменения разрешений root или ancestors. Нельзя принять чужой pre-created Run или автоматически исправить его permissions.

## Native identity и launch

1. Все production Hermes host paths, включая legacy `verify-safe-path` callers, используют component-by-component nofollow/native identity validation без host ACL inspection. Проверяются canonical containment, object type, отсутствие symlink/reparse, native volume/file или device/inode identity и соответствие exact pinned install layout. Путь из repository/model output не становится host authority. Windows exact volume-root proof через `GetFinalPathNameByHandleW(FILE_NAME_NORMALIZED | VOLUME_NAME_GUID)` и `FILE_ID_INFO` сохраняется; unsupported query, malformed path или другой volume fail closed.
2. Capture связывает complete chain с exact Run/attempt; одноразовый ticket передаёт versioned identity binding. Supervisor заново открывает каждый component относительно удерживаемого parent, проверяет ticket equality и удерживает цепочку через authoritative STOPPED. `authRootIndex` обозначает расположение Hermes auth root, а не начало private ACL policy; приватная граница явно связана с exact Run leaf. Alias, impostor, identity mismatch, reparse, невозможность безопасного open или sharing conflict закрывают запуск.
3. На Windows directory chain удерживается без `FILE_SHARE_DELETE`; write sharing для host directories и mutable Run directories не запрещается целиком. Image/launcher, config и immutable snapshot source files удерживаются с `FILE_SHARE_READ`, без write/delete sharing. Эти flags не означают неизменность DACL/owner/attributes или всего directory contents.
4. Normal production launch выполняет unconditional synchronous identity/source recheck непосредственно перед `CreateProcessW`, затем создаёт payload suspended с Job barrier, проверяет exact image и membership, принимает nonce ACK и повторяет synchronous identity/source/private-state checks непосредственно перед `ResumeThread`. Между последней проверкой и соответствующим OS вызовом нет await, observer callback или round trip. Evidence emission остаётся acceptance-only. Сейчас PRE_CREATE recheck в native helper включён только при `acceptanceEvidence`; реализация обязана устранить этот разрыв.
5. Source pin, clean Git source, exact launcher provenance и source snapshot manifest/digest/inventory сохраняются. Snapshot files удерживаются через весь Job lifetime. Snapshot integrity не утверждает защиту от злонамеренной модификации host-owned Python/DLL dependencies OS-authorized principal. Mutable host config читается через bounded nofollow handle и стабильное content/object read; Ebb потребляет только существующую allowlisted non-secret projection.
6. Run chain использует version 2 и exact поля `{version, authRootIndex, privateRootIndex, components}`: `privateRootIndex = authRootIndex + 2 = components.length - 1`, путь заканчивается `profiles/ebb-orchestrator-run-<runId>`. Revised Hermes launch frame — EBB4; legacy EBB3 не допускается как authority нового path contract. Provider/runtime auth policy identity добавляет `path=local-mode-host-trust-private-state-v1` через deterministic `buildAuthPolicyIdentity`; это внутренний discriminator, не пользовательская настройка и не новый secret. Platform-independent process launch без Hermes ticket не получает этот chain contract. Старые evidence и resume fingerprint с прежней policy не backfill-ятся и не переинтерпретируются; mismatch закрывает resume. Existing Run ID, session ID, context hash, context_deltas/FK и STOPPED semantics не меняются.

Hermes остаётся единственным owner provider credentials и их refresh. Ebb не читает/копирует keys или auth store, не добавляет SecretStore mapping, HMAC key, `.env` setting или provider endpoint mapping, не сохраняет/хэширует raw endpoint URL. Auth/selection ambiguity, unsupported endpoint revision и provider failure сохраняют existing fail-closed behavior.

## Реализация в Plan20 Task5

**Task5B-H — bounded Windows/Linux host compatibility:** зависит от existing Task5A-WL native process foundation и нового независимого Plan20/security review этого host/private контракта без blockers. Выполняет перечисленные ниже Windows/Linux seams, policy versioning и provider-free compatibility acceptance; неизвестные Darwin architecture/CI/schema решения не входят в его approval и не блокируют его реализацию. PASS 5B-H не означает PASS всего 5B, 5A или Task5.

**Task5A-M — обязательный macOS native port:** отдельная последовательность design → independent architecture/security review → implementation → native/package/CI/provider-free gates. Его owner определяет Darwin boundaries и механизм в отдельном reviewed design; Proposal13 не разрешает выдумать port. Task5A-M не является predecessor Task5B-H. macOS runtime/profile/auth/live-session и same-Run recovery затем обязаны пройти собственные 5B/5C gates. Overall Task5 и Plan20 completion требуют закрытия обеих ветвей и всей трёхплатформенной evidence.

**POSIX boundary clarification:** native `fstat` остаётся источником type/device/inode/size/stability и private-state evidence; host uid/mode не интерпретируются как admission policy, не публикуются как host inventory и не исправляются. Каждый direct POSIX reader проверяет parent components через scoped descriptor-bound nofollow path, а не только O_NOFOLLOW на leaf. `openAbsoluteDirectory`/`openPosixDirectory` с private final target сохраняют uid/mode checks только на explicit Ebb-private target, никогда на host ancestors. Source cache root остаётся private, хотя его внешние ancestors могут быть group/other writable; host executable сохраняет required OS executable access и exact image identity, без blanket host write-bit rejection.

Generic strict verifier может оставаться для отдельного контракта, но ни один production Hermes path не должен снова проверять host ACL через него. OS-derived Windows PowerShell path и pinned Git Authenticode subject/thumbprint сохраняются; host ACL trust не требует TrustedInstaller exception.

## Acceptance и платформы

| Сценарий | Требуемый результат |
|---|---|
| Foreign/inherited FullControl на существующих host ancestor, Hermes root или общем `profiles` | Совместимый запуск при валидных identity/source/profile prerequisites; host ACL untouched, admission inventory отсутствует. |
| Linux disposable host ancestor/auth root/shared profiles с group/other grants (0775 и 0777 без обязательного sticky); host launcher/facts/stamp/config с shared-write bits | Provider-free resolver → POSIX readers/profile helper → real Linux launcher проходит при валидных private objects/pin/content/identity; flags не вызывают host admission rejection или repair. |
| Linux Ebb cache final root/lock/snapshot/projection/Run/home/config с неверным owner/private mode | Fail closed; private uid/mode checks не ослаблены при host compatibility. |
| Foreign grant, неверный owner или неполная private policy на Ebb Run/home/config/snapshot | Fail closed, без автоматической permission repair. |
| Capture→ticket→supervisor substitution, reparse, другой volume или digest mismatch | Fail closed до resume; если process создан, exact stop proof до cleanup. |
| Normal production PRE_CREATE | Проверка выполняется без evidence observer; suspended image/PRE_RESUME checks сохраняются. |
| Живой Job и удерживаемые source/image/config handles | Ordinary write/delete/replace запрещены sharing contract; handles освобождаются после exact stop. |
| Private Run ACL change между suspended creation и ACK | Resume запрещён, Job остановлен; restoration/cleanup только после fresh exact STOPPED и identity proof. |
| Неизвестный STOPPED или несовпадающий owner/attempt | Сохранить owner/capability/reservation/profile; cleanup и resume запрещены. |
| Old policy ticket/resume evidence | Fail closed без backfill и создания нового Run вместо исходного. |
| Provider/auth | Только существующий Hermes-native route; no secret copy, fallback или duplicate Ebb settings. |

Host-grant fixtures синтетические либо целиком disposable и test-owned. Тесты не инвентаризируют/изменяют разрешения volume root, user profile, установленного Hermes или других существующих host objects. Изменение disposable private fixture в race test сохраняет exact STOPPED-before-restoration contract.

**Task5B-H native acceptance:** добавить provider-free `apps/server/test/e2e/hermes-host-permission-compatibility.acceptance.test.ts`, с fixtures целиком под test-owned temp child. Команда: `pnpm --filter @ebb-orchestrator/server exec vitest run test/e2e/hermes-host-permission-compatibility.acceptance.test.ts`, после existing Windows/Linux helper builds и native scope prerequisites в их существующих CI jobs. Linux real launcher branch должен потребить fixture через POSIX resolver/direct readers/profile helpers; только unit mock не доказывает admission compatibility. Тест отдельно проверяет host 0775/0777 positive (без root/sticky exemption), private mode/owner negatives, symlink component/leaf, device/inode substitution, digest mismatch и authoritative STOPPED-before-cleanup. Native owner mismatch можно дополнить synthetic stat input, не создавать другого account, не выполнять host chown/elevation. Материализуются только public source/non-secret config fixtures; credentials не читаются. Проверка mode setup ограничена созданным disposable fixture и Ebb-private objects; existing host permissions не инвентаризируются и не изменяются. Existing source-snapshot/process-scope acceptance расширяется только relevant Linux cases, не заменяется новым mocked PASS.

Windows, Linux и macOS являются целевыми платформами. Общее разграничение host/private применяется ко всем; platform readiness требует собственного native nofollow/identity/containment/STOPPED и provider-free acceptance перед provider-backed launch. Linux существующая systemd/cgroup/source-isolation основа проверяется отдельно. macOS native foundation ещё требует отдельного port design и независимого review; Windows Job Object или Linux systemd semantics нельзя приписывать macOS. Task5A-M должен определить и доказать этот port до macOS readiness. Task5B-H может пройти отдельный scoped review и Windows/Linux gates до завершения 5A-M; отсутствие Darwin design/evidence не блокирует этот bounded fix. Overall Task5/Plan20 остаются incomplete до обязательной macOS 5A/5B/5C evidence. Отсутствие macOS proof не превращает Windows/Linux evidence в macOS PASS.
