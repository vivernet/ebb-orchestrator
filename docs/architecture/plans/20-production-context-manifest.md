# Production ContextManifest lifecycle for every Run binding

**Goal:** Persist an accurate, durable `ContextManifest` for every production Task, Epic, and Request Run, and make its exact prepared-input provenance govern safe resume.

**Architecture:** A deterministic `RunContextAssembler` consumes validated persisted domain inputs plus each existing role-specific caller prompt, then produces the exact final prompt and provenance DTO. `RunService` persists one Run and its manifest atomically before any Scheduler/runtime dispatch; SQLite remains authoritative. Recovery may resume only the original Run and its original Hermes session after the persisted input fingerprint and execution boundary still match, the accessible workspace is unchanged, and the prior Hermes process is proven stopped. The verified Hermes Agent `v0.21.5+9117.g08165d5` (source commit `08165d58931841cee713468ae89032af7c57060a`) accepts `hermes chat --query-file <path> --provider <provider_id> --model <model_id> --source <tag> --format stream-json` and emits/flushed a live `system/init.session_id` before credential and agent initialization. Task 5A is the provider-free supervised process-scope foundation; Task 5B must first make the approved Hermes-native per-Run profile/auth path safe, then add a bounded live JSONL observer, correlate the event to the durable Run owner, and compare-and-set the original ID while Hermes remains live. `hermes sessions list --source <tag>` is not a production capture mechanism: it is human-readable rather than JSON and can perform session-store side effects. Task 5C consumes only the durable session ID after restart and proven process stop. Hermes remains the sole owner of provider credential resolution. Each Run uses a fresh Hermes-native profile under the Hermes root that owns the configured auth store; it does not share the user's whole profile or copy auth files. This isolates per-Run profile state, not credentials: the pinned Hermes auth path checks the profile first and uses a read-only global-root `auth.json`/credential-pool fallback per provider. Read only the explicitly configured, non-secret provider/model/endpoint selection through a pinned, bounded, side-effect-limited projection. Do not infer selection from auth status/list commands. The launch pins the approved provider and model both in the fresh per-Run config and explicit `--provider`/`--model` CLI arguments. The Ebb config omits both Hermes fallback keys, the fresh profile does not inherit user config, and the pinned Hermes defaults provide an empty fallback chain; the source audit and regression tests establish that a selected-provider auth failure therefore fails the Run without switching providers. Hermes virtual `moa:` model routing is rejected because the pinned CLI gives it precedence over `--provider`. The stream event remains session-ID evidence only, not provider evidence. This route and no-fallback guarantee are versioned in the provider/auth policy identity. Hermes itself resolves and refreshes credentials through its supported native profile/global-auth route. Environment- or plugin-backed auth sources remain gated until separately proven. If selection, auth support, profile isolation, or native resolution is ambiguous or unsafe, fail closed before spawn. No provider-backed launch is enabled unless the bounded configuration, empty-plugin, profile-path, and real-provider gates pass.

**Authority:** User-approved production ContextManifest and Hermes auth direction in Proposals08/09; spec01; [Proposal13](../proposals/13-local-mode-host-permission-compatibility.md), whose host-permission compatibility and Windows/Linux/macOS direction was explicitly approved by the user on 2026-10-09. Bounded Task5B-H implementation requires fresh independent review of revised Plan20 Windows/Linux host/private and related lifecycle/auth/source contracts plus scoped security review with no blockers; pending Darwin design is tracked under required separate Task5A-M and is outside 5B-H scope. Task5A-M implementation requires its own independent design/security review; no repeat permission request to preserve host ACLs or remove their admission check is required.

**macOS support target:** Task5A-M/5B-M/5C-M must target **macOS 13.5 or newer on Apple Silicon (`arm64`)**; Intel is outside this approved support matrix. Use [Proposal15](../proposals/15-macos-production-process-containment.md) as the required design/feasibility record. The existing macOS workflow is fixture-only and cannot satisfy production readiness; native/package/CI acceptance must prove the supported production path, including the minimum OS floor or a documented equivalent acceptance strategy.

**Global Constraints:** Do not capture or claim hidden Hermes/system prompts, runtime-injected context, or Hermes conversation history. Do not backfill historical Runs with guessed manifests. Preserve each existing role's caller-owned prompt and mandatory structured inputs. A Run without its manifest is never dispatchable. Keep Run and manifest in one SQLite transaction. Persist the unique per-Run Hermes `source_tag`, native per-Run `HERMES_HOME`, containment identity, and launch nonce before spawn. Hermes owns provider configuration and native credential resolution/refresh. Do not add a duplicate Ebb SecretStore credential, Ebb provider-key environment injection, copied auth file, or shared whole user profile. Every Run uses a fresh native Hermes profile beneath the root that owns the configured auth store. It isolates per-Run profile state but does not isolate credentials: Hermes checks profile auth first, then uses a read-only global-root `auth.json` and credential-pool fallback per provider. Preserve the explicitly configured provider/model/endpoint using only a bounded non-secret projection; never infer selection from auth status/list. Provider identity is guaranteed by the exact selected provider/model being repeated in the fresh Run config and explicit `--provider`/`--model` args, plus the source-pinned empty-fallback policy. The generated config contains neither `fallback_providers` nor `fallback_model`, user config is not inherited, and the child environment does not inject fallback settings. A selected-provider auth failure must fail closed; a live provider call still remains a separate acceptance gate. Support only the source-audited Hermes-native auth route; plugin- or environment-backed sources remain gated until separately proven. Hermes resolves credentials; Ebb never reads or copies credential values. Missing, unsupported, ambiguous, or unsafe auth/config/profile conditions fail closed before spawn. The supported global-root fallback is Hermes-native shared auth, not copied or isolated per-Run credentials. Profile creation and config reads validate every component without following symlinks/reparse points and use handle/descriptor-bound operations. Existing host permissions/owner are never admission predicates; private per-Run/cache ownership/permissions remain required under Proposal13. If any platform cannot prove those controls, fail closed before Hermes spawn. A Hermes session ID is usable only when the version-pinned supervised process emits exactly one valid allowlisted `system/init.session_id` event while its exact durable owner is `LIVE`; correlate it to the immutable Run ID, `source_tag`, Hermes home, containment identity, and launch nonce, then compare-and-set `agent_runs.session_id` while that process remains alive. Persist capture validity separately from process state: after capture is `INVALID`, no later or stale callback may restore a resumable session. Missing, malformed, duplicate, out-of-bound, mismatched, or uncorrelated events and CAS failure fail closed. `hermes sessions list --source <tag>` is not a capture mechanism; do not use private Hermes SQLite, `latest`, inferred IDs, or post-close buffered stdout as authority. The bounded live observer may retain only the allowlisted session ID in memory long enough for the CAS and safe usage/status projection; never persist or expose raw JSONL stdout, event text/tool arguments, launch arguments, prompts, or potentially secret-bearing stderr in artifacts, logs, Run rows, or APIs. The controlled `submit_result` channel remains the authoritative structured role result; JSONL `result.text` is not authoritative. Only resume the same Run with the exact persisted session ID and exact prepared-input/execution fingerprint after authoritative proof the old process stopped; mismatch returns `RESUME_NOT_SAFE_WORKSPACE_CHANGED` and does not create or dispatch a concurrent Run. Keep exact unsupported token measurement `NULL`; never substitute a character/byte estimate. Use the approved repository configuration contract at `.ebb-orchestrator/project.yaml`; repository-authored changes remain untrusted candidates and must never be automatically applied. Context preparation binds only the active, explicitly approved Project Config revision/hash. Do not add `.orchestrator/` discovery or migration behavior. Preserve permission, approval, Scheduler, budget, and Git ownership boundaries; no provider/hosted CI actions are assumed approved by this plan.

**Provider identity for resume:** Bind only stable, non-secret provider/model/endpoint identity explicitly exposed by the pinned Hermes version's supported configuration projection. The endpoint identity/revision must be source-backed and mutation-sensitive: it must change whenever the effective endpoint changes, including a change to `api`/`base_url` under an unchanged provider alias. A provider or endpoint alias alone is insufficient when the effective endpoint can change beneath it. Never persist the endpoint URL or derive identity by hashing it. Do not introduce an Ebb-generated HMAC/fingerprint key, an Ebb SecretStore entry, a root `.env` value, or a user-supplied parallel mapping. If the pinned Hermes configuration exposes no source-backed revision/identity with this mutation guarantee, fail closed before creating the Run or manifest and record a sanitized `HERMES_ENDPOINT_ID_UNAVAILABLE` reason; do not spawn Hermes, retain the URL, or claim provider acceptance. This fail-closed case is an explicit supported outcome, not a missing fallback to implement.
