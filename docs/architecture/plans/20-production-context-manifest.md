# Production ContextManifest lifecycle for every Run binding

**Goal:** Persist an accurate, durable `ContextManifest` for every production Task, Epic, and Request Run, and make its exact prepared-input provenance govern safe resume.

**Architecture:** A deterministic `RunContextAssembler` consumes validated persisted domain inputs plus each existing role-specific caller prompt, then produces the exact final prompt and provenance DTO. `RunService` persists one Run and its manifest atomically before any Scheduler/runtime dispatch; SQLite remains authoritative. Recovery may resume only the original Hermes session after the persisted input fingerprint and execution boundary still match, the supported workspace snapshot is unchanged, and the prior Hermes process is proven stopped. Hermes runs through the user's already configured root/profile; Ebb does not create a per-Run profile/home or copy user Hermes config/auth. Hermes remains the sole owner of provider/model selection and credential resolution. The existing Ebb MCP tools are registered in memory through the pinned Hermes API before ordinary CLI discovery; no profile or config overlay is created. Task 5B verifies this narrow adapter call, real configured-provider invocation, and durable live `system/init.session_id` capture. Ebb does not inspect Hermes provider/model/endpoint/auth settings for a new Run or same-session resume. Hermes applies its current user-configured route when resuming. `hermes sessions list` or post-close output is not a production capture mechanism. Task 5A is the supervised process-scope foundation; Task 5C consumes only the durable session ID after restart and proven process stop. No provider-backed launch is accepted without real-provider evidence.

**Authority:** User-approved ContextManifest direction in Proposal08; Hermes provider reuse as amended by Proposal09 on 2026-10-10; spec01. Proposal13 remains relevant only to its explicit prohibition on host permission inventory/remediation, not as a per-Run Hermes profile contract. The macOS support target and its separate native design/review gates remain as specified below.

**macOS support target:** Task5A-M/5B-M/5C-M must target **macOS 13.5 or newer on Apple Silicon (`arm64`)**; Intel is outside this approved support matrix. Use [Proposal15](../proposals/15-macos-production-process-containment.md) as the required design/feasibility record. The existing macOS workflow is fixture-only and cannot satisfy production readiness; native/package/CI acceptance must prove the supported production path, including the minimum OS floor or a documented equivalent acceptance strategy.

**Global Constraints:** Do not capture or claim hidden Hermes/system prompts, runtime-injected context, or Hermes conversation history. Do not backfill historical Runs with guessed manifests. Preserve each existing role's caller-owned prompt and mandatory structured inputs. A Run without its manifest is never dispatchable. Keep Run and manifest in one SQLite transaction. Persist the unique per-Run Hermes `source_tag`, containment identity, and launch nonce before spawn. Hermes owns provider/model configuration and native credential resolution. Do not add a duplicate Ebb credential, provider-key environment injection, or copied user Hermes config/auth. Use the existing user-configured Hermes root/profile for every invocation. Register existing Ebb MCP tools in memory through the pinned Hermes API; do not add a profile/config overlay or another configuration subsystem. Do not parse auth files or inspect credential values. Do not replace Hermes' configured provider/model. The bounded live observer may persist only the allowlisted session ID after correlating the exact Run, owner, source tag, containment identity, and launch nonce while the process is `LIVE`; missing, malformed, duplicate, out-of-bound, mismatched, uncorrelated events or CAS failure fail closed. `hermes sessions list` and post-close buffered stdout are not capture authority. Never persist or expose raw JSONL stdout, event text/tool arguments, prompts, or potentially secret-bearing stderr in artifacts, logs, Run rows, or APIs. `submit_result` remains the authoritative structured role result. Resume only the same Run and exact persisted session after authoritative old-process STOPPED proof, available fingerprint checks, and unchanged workspace. Hermes resolves the current provider/model/auth from its existing configuration; Ebb does not compare, inspect, or require provider-context identity for resume. Keep exact unsupported token measurement `NULL`; never substitute a character/byte estimate. Use the approved repository configuration contract at `.ebb-orchestrator/project.yaml`; repository-authored changes remain untrusted candidates and must never be automatically applied. Context preparation binds only the active, explicitly approved Project Config revision/hash. Do not add `.orchestrator/` discovery or migration behavior. Preserve permission, approval, Scheduler, budget, and Git ownership boundaries; no provider/hosted CI actions are assumed approved by this plan.

**Provider identity for resume:** Provider/model/context identity is outside Ebb's resume gate. Ebb uses the same durable Run/session and validates its own manifest/workspace/process state, then invokes Hermes resume through the user's configured root/profile. Hermes applies its current provider/model/auth settings. Ebb does not inspect Hermes config, require a context revision, hash/persist endpoint URLs, or create identity keys/mappings. This means provider settings may have changed since the original Run; Hermes owns that routing behavior.

**Hermes host-path compatibility (user decision 2026-10-10):** Use the existing configured Hermes root/profile. Do not inventory or validate ACL/DACL, owner, mode, or foreign grants on host/Hermes paths or Ebb-owned host paths; do not change permissions. Keep only ordinary exact-path, expected-file-type, and no-follow checks directly required for process launch, source integrity, or cleanup. There is no per-Run Hermes profile, profile identity chain, profile-private permission contract, or profile cleanup requirement. Proposal13 is not authority to reintroduce such checks.

For the Windows launch ticket, no Hermes Run-profile/home/config identity is captured. Keep only the native process-scope identity and authoritative STOPPED proof required by Task5A, plus exact executable/source checks needed to launch the pinned runtime. Do not add ACL/DACL, owner, or profile-chain checks for the user Hermes root/profile or temporary Ebb artifacts.
