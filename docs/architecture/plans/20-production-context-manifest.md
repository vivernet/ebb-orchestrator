# Production ContextManifest lifecycle for every Run binding

**Goal:** Persist an accurate, durable `ContextManifest` for every production Task, Epic, and Request Run, and make its exact prepared-input provenance govern safe resume.

**Architecture:** A deterministic `RunContextAssembler` consumes validated persisted domain inputs plus each existing role-specific caller prompt, then produces the exact final prompt and provenance DTO. `RunService` persists one Run and its manifest atomically before any Scheduler/runtime dispatch; SQLite remains authoritative. Recovery may resume only the original Run and its original Hermes session after the persisted input fingerprint and execution boundary still match, the accessible workspace is unchanged, and the prior Hermes process is proven stopped. The Hermes CLI documents `--source` tagging, filtering with `hermes sessions list --source <tag>`, and resuming with `--resume <session_id>`; the documentation does not establish that an active non-interactive session is listable or define a stable machine-readable output contract. Task 5 therefore stages provider-free process-scope foundation before the mandatory version-pinned live-session proof; that proof gates authoritative session binding and resume implementation. If the supported CLI cannot produce exactly one parseable ID for the live Run's source tag, recovery remains blocked and no unsupported CLI flag, internal database query, `latest` lookup, or inferred ID is permitted.

**Authority:** User-approved `docs/architecture/proposals/08-production-context-manifest.md`; `docs/architecture/specs/01-system-design.md`.

**Global Constraints:** Do not capture or claim hidden Hermes/system prompts, runtime-injected context, or Hermes conversation history. Do not backfill historical Runs with guessed manifests. Preserve each existing role's caller-owned prompt and mandatory structured inputs. A Run without its manifest is never dispatchable. Keep Run and manifest in one SQLite transaction. Persist the unique per-Run Hermes source tag before spawn. A Hermes session ID is usable only when the supported, version-pinned CLI proves exactly one session for that tag while the matching Hermes process identity is recorded; persist that original ID with compare-and-set before any recovery/resume can use it. `hermes sessions list --source <tag>` is a documented candidate lookup, not proof of active-session visibility or output format; Task 5 must establish those facts by provider-backed acceptance. If it cannot, keep recovery unavailable and retain the Run owner; never infer an ID from buffered stdout after process exit, set `HERMES_SESSION_ID` manually, inspect Hermes private SQLite state, use `latest`, or invent flags. Only resume the same Run with the exact persisted session ID and exact prepared-input/execution fingerprint after authoritative proof the old process stopped; mismatch returns `RESUME_NOT_SAFE_WORKSPACE_CHANGED` and does not create or dispatch a concurrent Run. Keep exact unsupported token measurement `NULL`; never substitute a character/byte estimate. Repository configuration lives under `.ebb-orchestrator/`; do not add `.orchestrator/` discovery or migration behavior. Preserve permission, approval, Scheduler, budget, and Git ownership boundaries; no provider/hosted CI actions are assumed approved by this plan.

**Affected plans:** Plan05 and Plan06 consume this plan's production ContextManifest evidence after their own remaining gates pass. They are downstream consumers, not prerequisites; Plan20 has no dependency on either plan.

**Review Focus:** JCS/digest rules have stable test vectors; all subject/role callsites consume one assembled DTO without losing caller prompts; transaction rollback prevents dispatchable or orphan Run/manifest state; migration preserves every existing `context_deltas` row and both foreign-key behaviors; resume is gated on a version-pinned Hermes session lookup proof and cross-platform process identity, compares ignored, staged, unstaged, untracked, and other readable regular-file state, and retains the prior owner until stop proof and existing terminalization/reconciliation; read API/UI never exposes prompt text, secrets, full knowledge text, or reasoning.
