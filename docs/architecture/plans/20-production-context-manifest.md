# Production ContextManifest lifecycle for every Run binding

**Goal:** Persist an accurate, durable `ContextManifest` for every production Task, Epic, and Request Run, and make its exact prepared-input provenance govern safe resume.

**Architecture:** A deterministic `RunContextAssembler` consumes validated persisted domain inputs plus each existing role-specific caller prompt, then produces the exact final prompt and provenance DTO. `RunService` persists one Run and its manifest atomically before any Scheduler/runtime dispatch; SQLite remains authoritative. Recovery may resume only the original Run and its original Hermes session after the persisted input fingerprint and execution boundary still match, the accessible workspace is unchanged, and the prior Hermes process is proven stopped. The pinned Hermes CLI's `--format stream-json` emits and flushes a live `system/init.session_id` event before credential and agent initialization. Task 5A is the provider-free supervised process-scope foundation; Task 5B must first make the approved Hermes-native per-Run profile/auth path safe, then add a bounded live JSONL observer, correlate the event to the durable Run owner, and compare-and-set the original ID while Hermes remains live. `hermes sessions list --source <tag>` is not a production capture mechanism: it is human-readable rather than JSON and can perform session-store side effects. Task 5C consumes only the durable session ID after restart and proven process stop. Hermes remains the owner of provider setup, credentials, and token refresh. The native-profile/default-auth-store direction is conditional: no provider-backed Hermes launch is enabled unless explicit provider/model selection, profile-path protections, and cross-process refresh recovery pass their specified gates.

**Authority:** User-approved `docs/architecture/proposals/08-production-context-manifest.md`; accepted Hermes provider-auth ownership direction in `docs/architecture/proposals/09-hermes-provider-auth-reuse.md`; `docs/architecture/specs/01-system-design.md`.

**Global Constraints:** Do not capture or claim hidden Hermes/system prompts, runtime-injected context, or Hermes conversation history. Do not backfill historical Runs with guessed manifests. Preserve each existing role's caller-owned prompt and mandatory structured inputs. A Run without its manifest is never dispatchable. Keep Run and manifest in one SQLite transaction. Persist the unique per-Run Hermes `source_tag`, native per-Run `HERMES_HOME`, containment identity, and launch nonce before spawn. Hermes owns provider configuration, credentials, credential resolution, and token refresh; never add a duplicate Ebb SecretStore credential, provider-key environment frame, copied auth file, or shared whole user profile. The selected implementation path is one Hermes-native profile at `<Hermes default root>/profiles/ebb-orchestrator-run-<run-id>` using only allowlisted explicit provider/model/endpoint scalars read from the default Hermes configuration; the Hermes-owned default/global auth store remains the credential source. Never use `hermes config get` as a presumed side-effect-free effective-selection API, parse/read credential material, or enable implicit `auto` provider selection. Profile creation and config reads must validate the native root and every path component without following symlinks/reparse points, enforce private per-Run ownership/ACLs, and use handle/descriptor-bound create/open/write/cleanup. If any platform cannot prove those controls, fail closed before Hermes spawn. If Hermes' pinned implementation cannot prove cross-process refresh serialization and crash/restart recovery for this exact profile/root topology, keep provider execution and resume disabled. A Hermes session ID is usable only when the version-pinned supervised process emits exactly one valid allowlisted `system/init.session_id` event while its exact durable owner is `LIVE`; correlate it to the immutable Run ID, `source_tag`, Hermes home, containment identity, and launch nonce, then compare-and-set `agent_runs.session_id` while that process remains alive. Persist capture validity separately from process state: after capture is `INVALID`, no later or stale callback may restore a resumable session. Missing, malformed, duplicate, out-of-bound, mismatched, or uncorrelated events and CAS failure fail closed. `hermes sessions list --source <tag>` is not a capture mechanism; do not use private Hermes SQLite, `latest`, inferred IDs, or post-close buffered stdout as authority. The bounded live observer may retain only the allowlisted session ID in memory long enough for the CAS and safe usage/status projection; never persist or expose raw JSONL stdout, event text/tool arguments, launch arguments, prompts, or potentially secret-bearing stderr in artifacts, logs, Run rows, or APIs. The controlled `submit_result` channel remains the authoritative structured role result; JSONL `result.text` is not authoritative. Only resume the same Run with the exact persisted session ID and exact prepared-input/execution fingerprint after authoritative proof the old process stopped; mismatch returns `RESUME_NOT_SAFE_WORKSPACE_CHANGED` and does not create or dispatch a concurrent Run. Keep exact unsupported token measurement `NULL`; never substitute a character/byte estimate. Use the approved repository configuration contract at `.ebb-orchestrator/project.yaml`; repository-authored changes remain untrusted candidates and must never be automatically applied. Context preparation binds only the active, explicitly approved Project Config revision/hash. Do not add `.orchestrator/` discovery or migration behavior. Preserve permission, approval, Scheduler, budget, and Git ownership boundaries; no provider/hosted CI actions are assumed approved by this plan.

**Current implementation baseline:** The committed tree already contains most approved §10.2 lifecycle wording, provenance/digest implementation, manifest repository and migrations 037/038, role assembler, production Run/manifest transaction bindings, process-owner/Windows Job/Linux systemd supervision foundation, startup fail-closed ordering, and manifest API/UI. This Plan20 feedback update synchronizes §10.2's generic Context Budget/token-size language with the user's explicit decision A; Task 0 must verify and record that alignment, and must not require repeating the edit unless its baseline check finds a remaining discrepancy. Treat other existing implementation as baseline to verify, not recreate. In particular, migration 037/038 and `context_deltas` are immutable baseline: 038 adds `systemd_control_group`; current migration acceptance verifies full row/schema/index/root-page equality, both retargeted legacy-manifest FKs and their `CASCADE`/`SET NULL` actions, and `foreign_key_check`. The provider bridge still exists in the current runtime and is not compliant with Proposal09. Task5B profile/auth safety and live session capture, Task5C durable recovery, fresh native/provider acceptance, and cross-callsite production evidence remain open. Existing code presence alone does not mark a task accepted; each baseline task below requires its specified fresh verification and review.

**Affected plans:** Plan05 and Plan06 consume this plan's production ContextManifest evidence after their own remaining gates pass. They are downstream consumers, not prerequisites; Plan20 has no dependency on either plan.

**Review Focus:** JCS/digest rules have stable test vectors; all 13 unique production Task/Epic/Request subject-role pairs consume one assembled DTO without losing caller prompts; all 18 actual production producer bindings are exercised through production entry points, separately from three event-consumer cases; transaction rollback prevents dispatchable or orphan Run/manifest state; migration preserves every existing `context_deltas` row, both foreign keys with their original `ON DELETE` actions, indexes, and diagnostic-only semantics without rebuilding/copying the table; live `system/init.session_id` is captured and CAS-persisted before process close against exact owner/source/home/containment identity; malformed, duplicate, missing, or failed capture leaves the initial Run without a resumable session; raw model/tool stream and secret-bearing output never enter artifacts/logs/APIs; Hermes remains the sole provider-auth owner; resume is gated on durable same-Run/session proof and cross-platform process identity, compares ignored, staged, unstaged, untracked, and other readable regular-file state, and retains the prior owner until stop proof and existing terminalization/reconciliation; read API/UI never exposes prompt text, secrets, full knowledge text, or reasoning.
