## Exact E2E process ownership and frontend lifecycle

`apps/web/test/e2e/run-e2e.mjs` is the sole process orchestrator for `pnpm --filter @ebb-orchestrator/web test:e2e`. Before any child starts, it calls `allocateLoopbackPort()` twice: each helper binds a temporary `node:net` server to `127.0.0.1:0`, reads the assigned port, closes the probe, validates `1..65535`, and retries if a child reports `EADDRINUSE`. The launcher passes `backendPort` to `web-e2e-server.mjs` and passes the non-secret `EBB_E2E_BACKEND_URL=http://127.0.0.1:${backendPort}` to Vite. It passes `EBB_E2E_BASE_URL=http://127.0.0.1:${frontendPort}` to Playwright and starts Vite with the allocated `frontendPort`; no E2E port is a literal in the launcher, Vite config, Playwright config or spec. The backend URL and base URL contain no credential material and are the only URL handoff values.

`apps/web/vite.config.ts` reads `EBB_E2E_BACKEND_URL` only when `mode === "e2e"`, validates an exact `http://127.0.0.1:<1..65535>` origin, and uses it for the `/api` proxy target and `Origin` header; missing or non-loopback configuration fails startup. It has no E2E fallback to a fixed port. `apps/web/playwright.config.ts` reads and validates `EBB_E2E_BASE_URL` in launcher mode, uses it as `use.baseURL`, and sets `webServer: undefined`; it contains no bootstrap path, fixed base URL, backend command or second Vite/backend process. Direct `playwright test` without launcher-provided URLs is unsupported and fails with a configuration error.

The launcher builds the server first, starts `web-e2e-server.mjs` with the allocated backend port, waits for the backend's exact health response `200 {"status":"ok","lifecycle":"READY"}`, then starts Vite and waits for an HTTP `200` response from `EBB_E2E_BASE_URL/`; only after both readiness checks does it start Playwright with `EBB_E2E_SERVERS_STARTED=1`, `EBB_E2E_BASE_URL`, `EBB_E2E_BACKEND_URL`, `EBB_E2E_PASSWORD_CHANNEL` and `EBB_E2E_CONTROL_CHANNEL`. `v1-ui.spec.ts` uses relative requests through Playwright's `baseURL`; it never constructs a backend URL, reads a port, reads bootstrap state or calls a fixed health URL.

Readiness is a hard gate: if either child exits before its expected HTTP response, the response has the wrong status/body, the URL is not exact loopback, or the readiness deadline expires, `run-e2e.mjs` records the child/configuration failure, returns non-zero, and still enters cleanup. Cleanup is deterministic and failure-visible: stop Playwright first, then Vite, then the backend; await each process-tree exit and backend `stopped` acknowledgement, dispose credential/control channels, verify no child remains, verify lock and SQLite sidecar cleanup, and remove only the isolated `EBB_ORCHESTRATOR_HOME`. Any teardown timeout, failed acknowledgement, surviving child, lock/SQLite sidecar, or failed home removal makes the launcher fail; cleanup is not a warning or best-effort path. `web-e2e-server.mjs` owns only the backend lifecycle and never starts or embeds Vite; the browser always uses the launcher-owned Vite at the configured dynamic `baseURL`.
