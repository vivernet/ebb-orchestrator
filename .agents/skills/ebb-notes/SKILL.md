# Ebb Notes

Работа с реестром входящих предложений пользователя `docs/roadmap/notes.md` (`kind: notes`). Реестр — неавторитетный источник: записи не являются утверждёнными планами и сами по себе не разрешают реализацию.

## Инварианты целостности

1. Единственный источник истины — файл `docs/roadmap/notes.md`. Не создавать других файлов для тех же записей.
2. **Перед любой записью или изменением всегда сначала прочитай текущий реестр целиком.** Это гарантирует корректную нумерацию, отсутствие дубликатов и актуальные статусы.
3. Идентификаторы `IN-NNN` уникальны и возрастают; новый id = максимальный существующий + 1.
4. Записи не удаляются: вместо удаления статус переводится в `declined` или `done`.
5. Frontmatter и формат реестра не меняются при добавлении записей.

## Workflow

1. **Чтение.** Прочитай полный реестр. Показывай компактную сводку: id, дата, источник, статус, summary, `linked_plan`.
2. **Фильтрация.** По запросу фильтруй по статусу (`open | considered | promoted | declined | done`), источнику (`user | ai-suggestion`) или наличию `linked_plan`.
3. **Добавление записи.** Только с явного разрешения пользователя. Проверь отсутствие дубликата по смыслу; назначь следующий id; заполни `date`, `source`, `status: open`, `summary`, опционально `context`/триггер. `linked_plan` не заполняется до promote.
4. **Предложение ИИ.** Кандидаты на новые записи сначала представь отдельным списком и запроси разрешение. Без явного согласия в реестр ничего не пишется.
5. **Перевод статусов.** `considered` — после рассмотрения при планировании; `promoted` — только при наличии существующего плана (укажи `linked_plan`); `declined` — с краткой причиной; `done` — после исполнения. Все переходы — только с подтверждения пользователя.
6. **Сверка с планированием.** `ebb-write-plan` (шаг 3) обязан учитывать открытые записи; этот skill поддерживает реестр в актуальном состоянии для этой сверки.

## Проверка после изменения

- Повторно прочитай изменённый реестр: id уникальны, статусы из допустимого набора, формат сохранён.
- `pnpm docs:check` и `git diff --check` должны проходить.
